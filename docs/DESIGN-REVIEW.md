# PO-гейт и дизайн-ревью v5

Дата: 22.11.2026. Версия: `prototype/index.html` (v5, стили из живого виджета).
Скоуп: **только виджет покупки**. Сайт кинотеатра, афиша сайта и его навигация не меняются.

Роли: PO-гейт и дизайн-ревью проведены по чеклистам `product-pipeline` (check/agree), `ui-craft-floor` (режим Working, команда polish) и `web-design-guidelines`. Независимый человек-ревьюер в сессии не подключён — это честно отмечено в конце, а не выдано за подпись.

## 1. PO-контракт

| Пункт | Решение |
|---|---|
| Пользователь | зритель «Горизонта» на телефоне, уже выбрал сеанс |
| Работа | выбрать места по понятной цене, оформить, оплатить, получить билет |
| Успех | оформление не содержит лишних преград: сводка видна, ошибки объяснены, кнопка активна, оплата не теряет заказ |
| В scope | афиша внутри виджета, зал, оформление, оплата, успех, вход, ошибки, адаптив 320/390/1280 |
| Не в scope | сайт кинотеатра, выбор фильма на сайте, аналитика, реальный эквайер, доставка письма |
| Ограничения | цена/зоны/лимит — из данных проекта; реальный платёж не проводился; тёмную/бумажную стилистику не возвращать |
| Приёмка | пройдены `qa-redesign` и `qa-dom` на 320/390/1280; на оформлении нет декоративных линий и двойных рамок; отступы из 4/8/16/24; визуал сверен с кадрами v5 |

## 2a. Три состояния после «Оплатить»

| Состояние | Что видит человек | Где |
|---|---|---|
| Проверяем оплату | «Проверяем оплату. Повторно платить не нужно» + проверка статуса при задержке | экран оплаты |
| Оплата прошла, билеты формируются | «Оплата прошла — готовим билеты», кнопка неактивна | экран оплаты, отдельный шаг статуса |
| Билеты готовы | Билет с QR, чек, «Открыть билеты» | экран успеха |

Экран успеха появляется только после шага «готовим билеты», а не сразу по факту ответа банка. Номер заказа и данные о входе в зал не выдумываются: в прототипе их нет, пока продукт не подтвердит формат.

## 4. Дизайн-ревью

**Иерархия.** Сначала сводка заказа, затем получатель, затем оплата. Заголовки секций — 12 px, uppercase, `#727276`; это единственный служебный капс, он взят из живого виджета. Главное действие — одна синяя кнопка в футере. На десктопе оформление 520 + 320; оплата — одна панель 680 с суммой справа и горизонтальным статусом.

**Поверхности.** Белый лист + серая сводка + одна сгруппированная карточка способов оплаты + голубая выбранная строка. Теней на карточках нет; тень только у плавающих слоёв. Вложенных карточек нет.

**Типографика.** Системный sans-serif, 400/600. Нижняя граница 12 px, основной текст 14–15, названия фильмов 18–20/600, состояния 22–26/600, суммы 22–38. Georgia и «редакционные» заголовки удалены.

**Состояния.** Поля: default/hover/focus/error. Оплата: default/hover/selected/disabled. Кнопка: default/hover/pressed/disabled. Вход: провайдер/почта/СМС/ошибки. Всё проверено в `qa-dom`.

**Доступность.** Фокус виден, тач-таргеты 36–48, кресло 24, ошибки с текстом и рамкой, `prefers-reduced-motion` отключает движение. Контраст: основной 15.9:1, вторичный 8.8:1, тихий 4.95:1, синий 4.97:1.

## 5. Что осталось открытым

1. **Независимая подпись.** PO-гейт и дизайн-ревью проведены в одной сессии; отдельного человека-ревьюера нет. Перед сдачей нужен второй проход по кадрам `audit/after/v5-app/`.
2. **Токены.** Значения взяты из `tokens.dtcg.json`, но пока продублированы локальными переменными в `styles.css`; перед продакшном заменить на `var(--color-*)`.
3. **Шрифт.** Системный стек соответствует текущему виджету, но не решает вопрос фирменного Manrope.
4. **Реальные данные.** Постеры и сеансы демонстрационные; платёж и доставка билета имитируются.
