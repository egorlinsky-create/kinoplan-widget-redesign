# Приоритизация фич — MoSCoW

Дата: 23.11.2026, версия после UX-аудита и повторной проверки бенчмарка. Источники:
[features_list.md](features_list.md), [AUDIT-HEURISTIC.md](AUDIT-HEURISTIC.md),
[competitor_features.md](competitor_features.md), [HYPOTHESES.md](HYPOTHESES.md),
[personas.md](personas.md), [interview_marina.md](interview_marina.md), [RATIONALE.md](RATIONALE.md).

Критерии Must have: фича закрывает JTBD primary-персоны (Марина), без неё основной сценарий
невозможен или содержит подтверждённый сбой severity 3–4, либо это table stakes по бенчмарку.
Фича вне границ виджета (поиск, фильтры, площадка, лояльность) в Must не попадает, даже если
полезна сайту. F-номера — служебная нумерация для сверки; в презентации — названия.

## Что изменилось 23.11 после аудита

- **F1 (цена «от») — из Could в Must.** В живом виджете цены в карточке сеанса нет вообще,
  а у КАРО и Фритауна она есть: сравнивать сеансы по цене сейчас нельзя без входа в зал.
- **F2 (зоны в легенде) — из Should в Must.** Легенда статична, A/B не требует; без неё одна
  цена в зале при разных тарифах вводит в заблуждение. Включается только при данных кассы.
- **F3 (тултип с ценой) — из Should в Must.** Ховер и тап с ценой есть почти у всех; проблема
  не в показе, а в иерархии: у нас цена одного веса с рядом и местом и теряется. Это читаемость,
  а не A/B: цена 25 px, ряд и место — 11 px. В прототипе поправлено.
- **F17 (гостевая покупка) — из Must в Should.** Гость в живом виджете уже проходит; реальный
  дефект — ложное обещание входа (A5). В MVP его убираем, а работающий вход — после MVP.
- **F26 (события воронки) — в Must.** Без событий не измерить ни один эффект и не провести A/B.

## Must have — 13 фич первой версии

| Фича | Обоснование |
|---|---|
| F1 Цена «от» в карточке сеанса | Аудит A2/A3: цены нет, сравнение сеансов невозможно. КАРО и Фритаун показывают «от» — table stakes. Данные — минимальная цена из кассы |
| F2 Ценовые зоны ≤3 в легенде | Аудит: в больших залах зоны уже есть (430/500/530 ₽), в проверенном Зале 5 — одна цена. Задача — постоянство: зоны во всех залах с тарифами, при одной цене — честная одна цифра |
| F3 Тултип места с ценой | Ховер/тап с ценой — стандарт; у нас цена теряется. Фикс: цена 25 px главная, ряд и место — 11 px вторичны. В прототипе уже так |
| F4 Крупные кресла и зона попадания | Аудит A6: кресло ≈13–14 CSS px по кадру, промах добавляет билет. Цель ≥24 px, зона ≥44 px |
| F5 Зал на весь экран + зум | Аудит A9: зал в узкой полосе, под ним пустота; без зума не выбрать в большом зале |
| F6 Нижний лист выбранных мест | Аудит A3/A9: тултип и чипсы перекрывают зал, правка выбора невозможна |
| F9 Разрешение конфликта мест | Аудит: отказ по занятому месту молчаливый, тупик. Смежные альтернативы возвращают в сценарий |
| F13 Один экран оформления | Аудит A7: контакты и проверка заказа — два экрана с одной задачей, между ними теряется контекст |
| F14 Сводка заказа на вводе данных | Аудит A7: на «Контактах» нет фильма, мест и суммы — человек вводит данные вслепую |

| F22 Экран «Билеты готовы» | Аудит A1 severity 4: после оплаты нет билета; «вернитесь на этот экран» не работает. Проектное предложение: QR + email |
| F23 Состояние «оплата обрабатывается» | Аудит A1: нет статуса, страха двойной оплаты; нужна проверка и блокировка повтора |
| F26 События по шагам воронки | Без `screen_view → seat_select → checkout_view → paid` не измерить эффект и не провести A/B по F3 |

## Вывод

**13 Must, 11 Should, 3 Could, 2 Won't.** Граница MVP проходит по F26: всё, что выше, входит
в первую версию; первый кандидат v1.1 — F10 (восстановление прерванной покупки). F1, F2 и F3 —
новые Must: цена в сеансе, зоны в легенде и читаемая цена в тултипе. Рынок это уже делает;
наша задача — сделать читаемее, а не изобрести. F17 больше не Must: гость и так проходит,
чинить нужно ложный вход.

Перенос в прототип: `prototype/index.html` покрывает F3–F6, F13–F14, F16, F22–F23; F1, F2 и F26
нужно проверить отдельно — их в текущей сборке может не быть.
