# Что меняется по экранам

Коротко: было 4 экрана виджета и два экрана с данными → стало 3 шага и один ввод данных.
Ниже — построчно, что именно заменено и зачем. Макеты: `prototype/index.html`, скриншоты «после» — в `audit/after/`.

## Шаг 0. Вход и профиль (добавлено после замечания)

**Было** — в шапке виджета иконка «аккаунт» без подписи (ведёт в никуда для этого кинотеатра), на «Контактах» кнопка «Войти или зарегистрироваться» без работающего сценария. В первом редизайне эту ветку я убрал целиком и оставил только гостевой путь — это была ошибка.

**Стало** (`audit/after/14-auth-phone.png` … `19-profile.png`):

| Что | Как | Зачем |
|---|---|---|
| Вход в шапке афиши | Кнопка **«Войти»** с иконкой и подписью; после входа — имя в аккаунте, тап ведёт в профиль | Постоянная и понятная точка входа, а не безымянная стрелка |
| Вход по номеру | Телефон → код из СМС (4 цифры), без пароля | Привычный для России вход; пароль — лишний барьер |
| Альтернативы | «Войти по email», «У меня есть билет — войти по его номеру», «Продолжить как гость» | Три реальных случая: своя почта, билет куплен гостем, не хочу аккаунт |
| Гость не блокируется | Кнопка «Продолжить как гость» на экране входа и ссылка на оформлении | Регистрация не должна быть условием покупки |
| Ошибка кода | Красная подсветка полей + «Код не подошёл. Запросите новый»; повторная отправка с таймером 00:59 | Человек не застревает на экране кода |
| Возврат после входа | Шторка закрывается, человек остаётся на том же экране; места и введённые поля сохранены (udit/after/20-auth-sheet.png, 21-auth-returned.png) | Вход не должен ломать уже сделанный выбор |
| Конфликт контактов | Если человек уже ввёл email и он отличается от аккаунта — данные аккаунта побеждают, но появляется тост «Контакты заменили на данные аккаунта — Вернуть введённые» | Молча подменить адрес, на который ждут билеты, нельзя |
| Способ открытия | **Мобильный — нижняя шторка, десктоп — правая панель 392 px** поверх текущего экрана, не отдельная страница (udit/after/38-auth-desktop-panel.png) | Отдельная страница /account/login выкидывает из сценария; шторка на всю ширину на десктопе непригодна — поля по 900 px |
| Оформление для авторизованного | Строка «Вы вошли · +7 900 123-45-67 · сохранённая карта · Выйти» одной строкой (udit/after/44-checkout-profile-strip.png) | Минус два поля и минус ошибки ввода; телефон не переносится посимвольно |
| Сохранённая карта | «Банковская карта •••• 4242 · сохранена» первой в списке | Меньше шагов на экране оплаты |
| Бонусы | «Списать 120 бонусов» → −120 ₽ в итоге, в пределах 30% заказа | Причина заводить аккаунт и возвращаться |
| Профиль | Мои билеты (предстоящий и прошлый), чек, возврат, Пушкинская карта, выход | После покупки есть куда вернуться |

**Принцип:** авторизация — ускоритель, а не шлюз. Гость проходит весь сценарий; вход экономит шаги и даёт бонусы.

## Границы виджета (правка после замечания)

Мы делаем виджет, а не сайт: всё, что относилось к афише сайта, из виджета убрано.

| Что | Как теперь |
|---|---|
| Первый экран | шапка «Выбор сеанса» + дата + фильмы и сеансы. Поиск, фильтры и сортировка **убраны** — это функции сайта (udit/after/66-widget-entry.png) |
| Два режима входа | из сеанса — сразу схема зала с полосой сеансов; из общей кнопки — короткий выбор сеанса без афиши сайта |
| Закрытие | крестик и Escape, без внешней навигации сайта |
| Ограничения встраивания | описаны в WIDGET.md: iframe до 1260×971, мобильный — новая вкладка, платёж с редиректом, сторонние cookie |

## Адаптив и доступность

- **Мобильный** — основной макет 390×844; кресла, лист, CTA в зоне большого пальца.
- **Десктоп** (`audit/after/11-desktop-afisha.png`, `after/12-desktop-seats.png`, `after/13-desktop-checkout.png`) — две колонки: слева зал или форма, справа постоянная панель заказа. Раньше десктоп был растянутым мобильным макетом с пустой правой половиной.
- **Доступность:** заголовки h1/h2 на каждом экране, у иконок `aria-label`, кресла — кнопки с состоянием, поле ошибки связано с полем, нет запрета масштабирования, контраст текста ≥ 4.5:1 для основного и ≥ 3:1 для крупного.





## Зум схемы колесиком

На экране зала колесо мыши над схемой меняет масштаб кресел, а не прокручивает страницу: шесть шагов от 16 до 26 px, один шаг на 40 px прокрутки. Точка под курсором остаётся на месте — вертикальный скролл зала пересчитывается пропорционально шагу, иначе схема «убегает» при каждом тике.

- Кнопки «− +» над схемой делают те же шаги, клавиатура и трекпад работают как раньше.
- Shift или Alt + колесо отдают событие браузеру: обычная прокрутка зала остаётся доступной.
- Колесо меняет только размер кресла (`--seat-size`), картинка не масштабируется: подписи мест остаются читаемыми.
