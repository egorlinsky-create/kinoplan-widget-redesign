# Вопросы к состояниям (то, что я должен был задать сам)

Список проверок, который интерфейсник обязан пройти до сдачи экрана. Родился после конкретного промаха: я нарисовал карточку фильма с тремя сеансами и не спросил, что будет, если их восемь.

Формат: вопрос → что должно быть → статус в макете.

---

## 1. Количество объектов

| Вопрос | Что делать | Статус |
|---|---|---|
| Сколько сеансов у фильма в день? Бывает 1, 4, 8, 30 | Показывать 6 и «Ещё N сеансов» с раскрытием; при 1 — не рисовать сетку на 3 колонки с пустотой | **Есть**: у первого фильма 8 сеансов, 5 скрыты за кнопкой `audit/after/43-afisha-all-sessions.png`. При 1 сеансе — сетка `auto-fit`, кнопка не показывается |
| Сколько сеансов в полосе зала? | Горизонтальный скролл, текущий виден, без обрезки цены | есть |
| Сколько фильмов в афише? 1 или 40 | Бесконечный список с датами, фильтр по времени; пустая афиша — отдельное состояние | **готово**: пустая дата даёт состояние «На 23 ноября сеансов нет» с переходом на 24-е (udit/after/46-empty-date.png) |
| Сколько мест в зале? 30 или 400 | Схема с зумом, авто-подгонка по ширине; для больших залов — миникарта | **готово частично**: зал 396 мест рисуется компактно (15 px), прокручивается, легенда и цены пересчитаны (udit/after/47-big-hall.png); миникарты пока нет |
| Сколько мест выбрано? 0, 1, 6, попытка на 7-е | Лимит виден заранее, отказ объясняется | есть |
| Сколько зон цен? 1, 3, 5 | Легенда при 1 зоне не показывается; при 5 — сетка легенды | **не сделано** для 5 зон |

## 2. Длина текста

| Вопрос | Что делать | Статус |
|---|---|---|
| Фильм называется на 60 символов? | 2 строки + `title` | есть |
| Зал называется «Зал «Премьер» IMAX Dolby»? | 2 строки с эллипсисом, цена отдельной строкой | есть |
| Цена `от 10 500 ₽`? | Отдельная строка, табличные цифры | есть |
| Email длиной 40 символов? | Эллипсис в поле, полный текст по фокусу | есть |
| Имя кинотеатра и адрес длинные? | 2 строки в шапке, `title` | есть |
| Телефон в строке профиля? | Одна строка, эллипсис, кнопка «Выйти» справа | **исправлено**: до этого телефон переносился посимвольно, строка занимала 180 px |

## 3. Пустые и крайние состояния

| Вопрос | Что делать | Статус |
|---|---|---|
| Нет сеансов на дату | Объяснение + ближайшая дата со сеансами | **не сделано** |
| Весь зал занят | Сообщение и предложение другого сеанса | **готово**: экран «На этот сеанс мест нет» с двумя выходами, в полосе сеансов — «мест нет» (udit/after/48-sold-out.png) |
| Нет свободных мест рядом | Предложение альтернатив | есть (экран «Места заняли») |
| Место без цены / цена 0 (бесплатный показ) | Не писать «0 ₽», писать «Бесплатно» | **готово**: единая функция подписи цены (ub/priceLabel) |
| Один фильм в афише | Не растягивать карточку на всю ширину списка | **не сделано** |
| Пользователь не вошёл | Гостевой путь без блокировки | есть |
| Сессия истекла во время оплаты | Вернуть к заказу с объяснением | **готово**: таймер брони по нулю ведёт на экран «Бронь истекла, но заказ сохранён» с возвратом к выбору мест |

## 4. Оплата

| Вопрос | Что делать | Статус |
|---|---|---|
| Способ оплаты выбирается один раз | Выбор на оформлении; на оплате — только форма выбранного способа и ссылка «Изменить» | **исправлено**: убраны табы «Карта / СБП» на экране оплаты |
| СБП: что нажимать? | Одна основная кнопка «Открыть приложение банка»; после возврата — «Я оплатил, проверить» | **готово**: состояние «Проверяем оплату» со спиннером и ручной проверкой |
| Карта отклонена | Повтор, другой способ, места держим | есть |
| Сертификат не покрывает сумму | Показать остаток к оплате картой | **не сделано** |
| Пушкинская карта не подходит для фильма | Показать причину и не давать выбрать | **сделано**: «Для этого фильма не подходит — 18+» |
| Сортировка сеансов | «По времени» и «Сначала дешёвые» | **сделано** |
| Формат зала | Фильтр IMAX | **сделано** |
| Нет доступных способов | Объяснить и предложить оплату на кассе | **не сделано** |

## 5. Устройство и ввод

| Вопрос | Что делать | Статус |
|---|---|---|
| 320, 390, 768, 1180, 1440 px | Автотест ширины: ни один контрол не шире 380 px на десктопе, ничего не обрезано на 320 | есть (тест `_research/stress-test.mjs`) |
| Только клавиатура | Фокус, Enter/Space на местах, Esc закрывает шторку, Tab в пределах шторки | частично: зал — кнопки, но стрелочная навигация по схеме не сделана |
| Скринридер | Имена мест с зоной и ценой, `aria-live` на сообщениях | есть |
| Движение отключено | Все анимации 1 мс | есть |
| Медленная сеть | Скелетоны вместо пустых блоков | **не сделано** |
| Ошибка сети при входе | Текст «Не удалось проверить код…», ввод не стирается | описано, в прототипе не реализовано |

## Правило, которое я забираю в работу

Перед сдачей экрана — пройти этот список и отметить статус. Не «нарисовать один счастливый случай», а перечислить: **сколько объектов, какой длины текст, что при нуле, что при избытке, что при отказе**.

## Что закрыто в этой итерации

1. Пустая афиша и «нет сеансов на дату» — готово.
2. Весь зал занят — готово; зал на 400+ мест — готово без миникарты.
3. Бесплатные показы и цена 0 — готово.
5. Возврат к заказу после истечения брони — готово.
6. «Проверяем оплату» для СБП — готово.

## Осталось

4. Один фильм / один сеанс в списке — сетка уже uto-fill, но проверить на реальных данных.
7. Миникарта для залов 400+ мест.
8. «Нет доступных способов оплаты» и сертификат, не покрывающий сумму.
9. «Поделиться сеансом» для компании — согласование вне сервиса.
