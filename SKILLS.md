# SKILLS — проект «Киноплан»

## Бриф (20.11.2026)

```
Цель:        поднять UX и конверсию виджета продажи билетов на всех этапах
Для кого:    зрители кинотеатра, преимущественно мобильные; клиенты «Киноплан»
Результат:   UX-аудит, макеты изменённых экранов, список гипотез с эффектом
Ограничения: основной сценарий сеанс → места → оформление → оплата; мобильный первым
Готово, когда: есть аудит с проблемами и влиянием, кликабельные макеты всех изменённых
              экранов, гипотезы с метрикой проверки
```

## Выбор навыков

```
Ведущий:         product-pipeline — задача про флоу и конверсию, а не только про экраны
Вспомогательные: design-ux — сценарий и состояния; design-ui — визуальный слой прототипа
Не беру:         design-lead — второй intake не нужен; uxui-workflow — продукт не новый,
                 меняется существующий флоу
Figma:           figma_remote (официальный MCP) — подключён и авторизован;
                 work-in-figma + figma-use как контракт записи, проверка скриншотом
Инструменты:     Chrome DevTools Protocol (headless Chrome) для прохода по живому виджету
```

## Исследовательский набор (26.11.2026)

Подключены семь внешних research-навыков, адаптированных под «Киноплан» (лежат в профиле `~/.dsh/skills/kp-*`). Исходники: ux-research (rampstackco), research-synthesis (Anthropic), jtbd-framing (rampstackco), ux-researcher-designer (bestagentkits), interview-frameworks (slgoodrich), interview-synthesis (borghei), product-ux-research (kinhluan).

| Навык | Когда брать | Что даёт |
|---|---|---|
| `kp-ux-research` | нужен план исследования под вопрос | вопрос, метод, рекрутинг, гид, адресат находок |
| `kp-research-synthesis` | есть данные аудита/интервью | темы с частотой и цитатами, матрица инсайт → возможность |
| `kp-jtbd-framing` | спор о фиче, проверка рамки | работа зрителя, hire/fire-критерии |
| `kp-interview-frameworks` | нужен гайд и скринер | вопросы о прошлом, конспект в две колонки |
| `kp-interview-synthesis` | готовы транскрипты | темы с силой доказательства, дерево возможностей |
| `kp-ux-researcher-designer` | полный цикл: персоны → карта пути → тест | персоны на данных, journey, план теста, находки |
| `kp-product-ux-research` | выбор метода, эвристики, каденция | таблица «вопрос → метод → выборка», SUS, severity |

**Маршрут.** Непонятен вопрос → `kp-product-ux-research` (выбор метода) → `kp-ux-research` (план) → `kp-interview-frameworks` (гайд) → `kp-interview-synthesis` + `kp-research-synthesis` (разбор) → `kp-jtbd-framing` (работа зрителя) → решения в прототип и макеты. Персоны и карта пути — через `kp-ux-researcher-designer`.

**Чем адаптированы.** Убрано всё, чего в проекте нет: скрипты `persona_generator.py`, Confluence/Notion/Linear, панели рекрутинга, продакшн-аналитика. Вместо них — реальные источники: `audit/before/`, `_research/`, `docs/AUDIT-HEURISTIC.md`, прототип. Добавлены проектные правила: сегментов два, режимов покупки четыре, выборка меньше 20 — только `X из N`, прогноз помечается как прогноз, у находки обязателен адресат (гипотеза, правка экрана или открытый вопрос).

### Синтетические персоны, симуляция интервью, кейсы

Добавлены навыки `kp-synthetic-personas` (прото-персоны на данных проекта), `kp-simulated-interview` (вход в роль зрителя, edge cases, разбор по запросу) и `kp-discovery-cases` (разбор реальных кейсов покупки с владельцем в формате интервью). Вместе с `kp-persona-usability-sim` это цепочка: кейсы → персоны → симуляция интервью → эмуляция юзабилити-теста.

### Вёрстка в Figma

Навык `kp-figma-layout`: auto layout обязателен, отступы на шкале и переменных `spacing/*`, иерархия 40% (секции 64 / блоки 24 / карточка 16 / подпись 8), проверка ручного позиционирования и 8-pt сетки. Дополняет `figma-use`; источники — figma-designer, rad-spacing, design-auditor.

### Аудит вёрстки

Первый прогон — `docs/FIGMA-LAYOUT-AUDIT.md`: в файле не было переменных `spacing/*`, создана коллекция на шкале 0–64; найдено 311 значений вне шкалы в первой секции и 37/43 во второй и третьей, основная причина — дрейф мастер-компонентов (`Чип сеанса`, `Статус-бар`, `Сводка заказа`).

### Документация компонентов

Навык `kp-figma-component-docs`: структура док-блока как в Ant — имя, назначение, матрица вариантов с подписями осей, анатомия, свойства, правила, токены, доступность, история. Первый док-блок — «Кнопка» в ките.

### Кит, готовый для агента

Навык `kp-agent-ready-kit`: описания на всех компонентах, индекс по node id, страница правил, токены вместо значений и чек-лист перед сдачей. В ките появились блоки «Read me, agent · правила кита» и «Индекс компонентов», у 17 компонентов заполнено описание.
